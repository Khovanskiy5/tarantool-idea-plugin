# Руководство пользователя

Плагин добавляет в IntelliJ IDEA полный цикл разработки под
[Tarantool](https://www.tarantool.io/): запуск и отладку Lua-скриптов,
управление инстансами (локально, в Docker или в Kubernetes), просмотр
и редактирование данных через Database Tools, тесты luatest, схемы
конфигурации, просмотр файлов данных и генерацию типов
для автодополнения.

Плагин неофициальный и не связан с VK/Tarantool.

## Требования

| Что | Версия | Зачем |
|---|---|---|
| IntelliJ IDEA (Community или Ultimate) | 2026.1+ | платформа плагина |
| Tarantool | 3.x (проверено на 3.8) | интерпретатор; для типа и схемы конфигурации |
| tt CLI | 2.x (проверено на 2.14) | инстансы, просмотр .snap/.xlog, мастер проектов |
| EmmyLua2 (опционально) | 0.24+ | язык Lua: автодополнение, диагностика, Emmy-отладчик |

Установка инструментов на macOS: `brew install tarantool tt`.
Если бинарники не в PATH IDE — задайте пути в
**Settings → Tools → Tarantool**.

## Установка плагина

Собранный дистрибутив: **Settings → Plugins → ⚙ → Install Plugin from
Disk…** → выберите `tarantool-idea-plugin-<версия>.zip` → перезапустите IDE.

Сборка из исходников — см. [development.md](development.md).

## Новый проект

**File → New → Project… → раздел Generators → Tarantool.**

1. Задайте имя и расположение проекта.
2. Выберите шаблон `tt create`:
   * `single_instance` — приложение с одним инстансом;
   * `cluster` — кластер из нескольких инстансов;
   * `vshard_cluster` — шардированный кластер vshard;
   * `config_storage` — централизованное хранилище конфигурации.
3. После создания плагин выполнит `tt init` и `tt create` в каталоге
   проекта и покажет уведомление.

Для существующего кода достаточно открыть каталог: плагин не требует
специального формата проекта.

## Запуск скриптов

### Быстрый запуск открытого файла

Правый клик по `.lua`-файлу (в редакторе или дереве проекта) → **Run**,
либо `⌃⇧R` / `Ctrl+Shift+F10`. Конфигурация создастся автоматически.

### Конфигурация «Tarantool»

**Run → Edit Configurations… → + → Tarantool.** Поля:

| Поле | Значение |
|---|---|
| Скрипт | путь к `.lua`-файлу; поддерживаются макросы (`$PROJECT_DIR$` и др.) |
| Интерпретатор | пусто/`tarantool` — автопоиск; иначе явный путь |
| Аргументы | передаются скрипту после его пути |
| Рабочий каталог | по умолчанию корень проекта |
| Переменные окружения | стандартный редактор пар ключ-значение |
| LUA_PATH | флажок «Добавлять корень проекта и src/…» — `require('model.users')` работает без обёрток; ваше значение LUA_PATH сохраняется хвостом |
| Отладчик | флажок «tarantool -d» — см. ниже |

Ссылки `file.lua:line` в выводе кликабельны — и в трейсбеках
(`src/model/users.lua:25:`), и в строках журнала, где Tarantool печатает
имя файла без каталога (`users.lua:25 I>`): такие имена разрешаются
поиском по проекту.

### Отладка

Два независимых способа.

**Встроенный отладчик Tarantool** — флажок «Запустить со встроенным
отладчиком (tarantool -d)». Скрипт стартует под консольным отладчиком
luadebug в окне Run: `help` — список команд, точки останова, шаги,
печать переменных. Работает без дополнительных плагинов.

**Emmy-отладчик (графический)** — нужен плагин EmmyLua2. Настройка
одним действием: **Tools → Настроить Emmy-отладчик Tarantool**. Оно
кладёт хелпер `emmy_debug.lua` в каталог приложения (рядом
с `config.yaml`) и создаёт конфигурацию запуска
«Tarantool: attach debugger». Дальше:

1. Добавьте в код приложения (например, в начало модуля роутера):

   ```lua
   require('emmy_debug').attach_if_requested()
   ```

   Без переменной окружения `TARANTOOL_DEBUG` строка не делает ничего —
   её можно оставлять в коде постоянно.

2. Запустите инстанс с отладкой:

   ```sh
   TARANTOOL_DEBUG=1 tt start            # один инстанс
   TARANTOOL_DEBUG=router-001-a tt start # кластер: порт откроет только он
   ```

   В кластере указывайте имя инстанса — иначе все инстансы боролись бы
   за один порт отладчика (по умолчанию 9966, меняется `EMMY_PORT`).

3. Поставьте точки останова и нажмите **Debug** у конфигурации
   «Tarantool: attach debugger».

Точки останова срабатывают в коде, который выполняется после
подключения IDE: в функциях, вызываемых по запросам, триггерах,
файберах. Код старта приложения к моменту подключения уже отработал.

Хелпер использует режим «Tcp ( IDE connect debugger )»: слушает процесс,
подключается IDE. Обратный режим (`emmy_core.tcpConnect`) с Tarantool
не работает — роняет процесс с LuajitError. Библиотеку `emmy_core`
хелпер находит в установленной IDEA сам; нестандартный путь задаётся
переменной `EMMY_CORE_DIR`.

Кнопка Debug у конфигурации «Tarantool» отключена сознательно: свой
протокол отладки плагин не реализует.

## Управление инстансами

### Панель «Tarantool»

Внизу IDE, рядом с Terminal: таблица инстансов (`tt status`) — состояние,
PID, режим, готовность конфигурации и box. Кнопки: обновить, запустить,
остановить, перезапустить и **Консоль** — открывает `tt connect`
к выбранному инстансу во вкладке встроенного Терминала.

Консоль открывается именно в Терминале: интерактивному `tt connect`
нужен настоящий терминал (`/dev/tty`), в Run-консоли он падает
с «device not configured». SQL-режим — внутри консоли:
`\set language sql`.

### Конфигурация «tt (Tarantool CLI)»

**Run → Edit Configurations… → + → tt (Tarantool CLI)** — для
неинтерактивных команд, когда нужен именно запуск из Run
(до/после других конфигураций, с горячей клавишей):

| Команда | Что делает |
|---|---|
| `start` | поднять инстансы приложения |
| `stop -y` | остановить без подтверждения |
| `status` | таблица состояния |
| `check init.lua` | проверка синтаксиса |
| `log -f` | хвост журнала инстансов |
| `cat var/lib/.../00000000000000000000.snap` | расшифровка файла данных |

Приложение выполняется при старте инстанса один раз; после правки кода
нужен `restart` (или `stop`/`start`).

### Проверка синтаксиса

Правый клик по `.lua`-файлу (редактор или дерево проекта) →
**Проверить синтаксис (tt check)** — результат уведомлением.

## Режимы запуска: локально, Docker, Kubernetes

**Settings → Tools → Tarantool → Режим запуска** (настройка проектная,
хранится в `.idea/tarantool.xml`) — где живут инстансы:

* **Локально (tt)** — режим по умолчанию, всё как описано выше.
* **Docker (tt в контейнере)** — панель инстансов, tt-конфигурации,
  логи и кнопка «Консоль» выполняют `tt` внутри контейнера через
  префикс команды: например `docker compose exec tarantool` или
  `docker exec my-container`. Панель тогда исполняет
  `docker compose exec tarantool tt status -f json`, консоль —
  `... tt connect <инстанс>` и так далее. В образе должен быть
  установлен tt, а приложение — управляться им.
* **Kubernetes (kubectl)** — инстансы это поды. Панель показывает
  их список (`kubectl get pods -l <селектор>`): состояние
  (включая CrashLoopBackOff/Terminating), готовность контейнеров,
  счётчик рестартов и узел. Кнопка перезапуска делает
  `kubectl delete pod` — под пересоздаёт его контроллер
  (StatefulSet/Deployment); отдельного «запустить/остановить» нет,
  этим управляет контроллер. Логи — `kubectl logs -f` в Run-консоли,
  «Консоль» — `kubectl exec -it <под> -- <команда>` в Терминале
  (команда настраивается; `console` официального образа tarantool
  подключается к админ-консоли инстанса).

Что нужно для Kubernetes-режима: настроенный `kubectl` (текущий
контекст — ваш кластер), namespace и селектор меток в настройках.

Работа с данными (Database Tools) от режима не зависит — это обычное
IProto/JDBC-подключение по хосту и порту. Для Docker пробросьте порты
(`ports: "3301:3301"`), для Kubernetes — `kubectl port-forward` или
Service типа NodePort/LoadBalancer; после этого источник данных
подключается как к локальному инстансу.

Что остаётся локальным в любом режиме: мастер нового проекта,
`tt check` (проверяет файлы хоста) и генерация типов — им нужен
локальный tt/tarantool.

## Конфигурационные файлы

* **config.yaml** (кластерная конфигурация Tarantool 3) — автодополнение
  имён опций, документация по ним и проверка типов. Официальная схема
  снята с Tarantool 3.8 (`require('config'):jsonschema()`). Применяется,
  когда рядом лежит `instances.yml` либо в корне проекта есть `tt.yaml`.
* **tt.yaml** — схема окружения tt, составлена по исходникам tt 2.14:
  разделы `env`, `app`, `modules`, `repo`, `ee`, `templates`.

Имя активной схемы видно в статус-баре YAML-редактора.

## Просмотр .snap / .xlog / .vylog

Двойной клик по файлу снимка или журнала открывает YAML-расшифровку
(`tt cat`) в редакторе только для чтения. Вывод длиннее 20 000 строк
обрезается с пометкой; полную расшифровку смотрите `tt cat` в терминале.

## Просмотр данных через Database Tools (Ultimate)

В IntelliJ IDEA Ultimate плагин настраивает работу с данными сам.
При открытии tt-проекта с `config.yaml` он:

* регистрирует драйвер **Tarantool (shim)** — поставляемую с плагином
  обёртку над `org.tarantool:connector`, эмулирующую автокоммит.
  Без неё сохранение из редактора данных падает с `SQLException`
  в `setAutoCommit`: редактор оборачивает сабмит транзакцией даже
  в режиме Tx: Auto, а интерактивные транзакции Tarantool требуют
  IPROTO-streams, которых в JDBC-драйвере нет;
* создаёт источники данных по узлам кластера из `config.yaml`: роутеры
  и лидеры репликасетов (RO-реплики пропускаются), с логином и паролем
  из раздела `credentials` и SQL-диалектом Tarantool.

Остаётся запустить инстансы (панель Tarantool → «Запустить»)
и открыть источник в окне **Database**.

Семантика записи честная: каждая операция применяется сервером сразу,
`commit` ничего не делает, `rollback` предупреждает, что откат
невозможен, — групповой сабмит не атомарен (ограничение драйвера,
не IDE).

### Полный скан

Просмотр таблицы — это `SELECT` без индекса; по умолчанию Tarantool
запрещает его с ошибкой «Scanning is not allowed». Любой из способов:

* в `config.yaml` инстанса (рекомендуется для разработки):

  ```yaml
  compat:
    sql_seq_scan_default: 'old'
  ```

* либо в настройках источника данных, вкладка **Options → Startup
  script**: `SET SESSION "sql_seq_scan" = true;`
* либо в каждом запросе: `SELECT * FROM SEQSCAN t;`

После этого работают дерево таблиц, редактор данных с пагинацией,
SQL-консоль, экспорт — вся стандартная функциональность Database Tools.

### Ручная настройка источника

Нужна, только если автосоздание не подходит (нестандартная топология,
чужой проект без config.yaml):

1. Окно **Database → + → Data Source → Tarantool**; host, port,
   пользователь и пароль — из вашей конфигурации.
2. Database → ⚙ → **Data Sources…** → раздел **Drivers** → Tarantool →
   Driver Files → **+** → выбрать
   `~/Library/Application Support/JetBrains/IntelliJIdea<версия>/plugins/tarantool-idea-plugin/driver/tarantool-jdbc-shim.jar`.
3. В поле **Class** выбрать
   `com.khovanskiy.tarantool.jdbcshim.ShimDriver`.

Что нужно знать о данных Tarantool в SQL:

* видны спейсы, у которых задан `format` (см. `space:format{...}`);
* имена спейсов из Lua обычно в нижнем регистре — в SQL пишите их
  в кавычках: `SELECT * FROM "users"`;
* таблицы, созданные через SQL `CREATE TABLE`, кавычек не требуют;
* проверено с Tarantool 3.8 и драйвером connector 1.9.4: соединение,
  метаданные, первичные ключи, SELECT/INSERT/UPDATE, кириллица.

### SQL-диалект Tarantool

Плагин добавляет в список SQL-диалектов собственный «Tarantool»:
база SQL-92 плюс слова Tarantool — `SEQSCAN`, типы (`UNSIGNED`,
`STRING`, `SCALAR`, `VARBINARY`, `UUID`, `DATETIME`, `MAP`, `ARRAY`,
`ANY`) и настройки `SET SESSION` (`sql_seq_scan` и другие).
Ложных ошибок на конструкциях, которых нет в SQL-92, диалект
не показывает.

Автоматически созданным источникам диалект назначается сразу. Для
остальных: **Settings → Languages & Frameworks → SQL Dialects** —
назначьте «Tarantool» проекту, отдельным файлам или консолям
(источник, добавленный вручную, по умолчанию получает Generic SQL
от встроенного конфига драйвера).

## Автодополнение по API Tarantool

Языковую поддержку Lua даёт плагин EmmyLua2 (языковой сервер emmylua_ls).
Наш плагин снабжает его описаниями API Tarantool. При открытии проекта
без типов он сам предложит их сгенерировать; вручную —
**Tools → Сгенерировать типы Tarantool**. Действие:

* снимает описания API интроспекцией с установленного интерпретатора
  и складывает их в `.types/tarantool/generated/`;
* кладёт уточнённые вручную сигнатуры частых API (спейсы, индексы,
  кортежи, файберы, net.box) в `.types/tarantool/manual/` — ваши правки
  в этом каталоге не перезаписываются;
* создаёт `.emmyrc.json`, если его ещё нет:

```json
{
  "runtime": { "version": "LuaJIT" },
  "workspace": {
    "library": [".types/tarantool/manual", ".types/tarantool/generated"]
  }
}
```

Повторяйте генерацию после обновления Tarantool. Точные сигнатуры
интроспекция дать не может (C-функции вариадические) — уточняйте нужные
в `manual/`.

## Live-шаблоны

В `.lua`-файлах, по Tab:

| Сокращение | Разворачивается в |
|---|---|
| `tspace` | `box.schema.space.create` + формат + первичный индекс |
| `tonce` | `box.once('key', function() … end)` |
| `tfiber` | создание файбера с `set_joinable` и `join` |
| `tatomic` | `box.atomic(function() … end)` |
| `tnetbox` | подключение `net.box` + `close` |
| `tlog` | именованный журнал `require('log').new(…)` |
| `twatch` | триггер `on_replace` на спейсе |

Список: **Settings → Editor → Live Templates → Tarantool**.

## Настройки

**Settings → Tools → Tarantool** — пути к `tarantool` и `tt`
по умолчанию. Пусто — автопоиск: PATH, затем `/opt/homebrew/bin`,
`/usr/local/bin`, `/usr/bin`. Путь в конкретной конфигурации запуска
имеет приоритет над настройками.

**Settings → Tools → Tarantool → Режим запуска** — проектный режим
исполнения (локально / Docker / Kubernetes), префикс docker-команды,
namespace, селектор подов и команда консоли — см. раздел
«Режимы запуска».

## Устранение неполадок

**«Интерпретатор tarantool не найден»** — IDE, запущенная из Dock, может
не видеть PATH вашего шелла. Задайте пути в Settings → Tools → Tarantool.

**Схема не применяется к config.yaml** — проверьте маркеры проекта tt:
`instances.yml` рядом с файлом либо `tt.yaml` в корне. Без них плагин
сознательно не трогает чужие config.yaml.

**Просмотрщик snap/xlog показывает ошибку** — прочитайте её текст: чаще
всего не найден tt (задайте путь в настройках) или файл битый; сообщение
дублирует stderr `tt cat`.

**`require` не находит модули проекта** — включён ли флажок LUA_PATH
в конфигурации запуска; модуль ищется как `<корень>/?.lua`,
`<корень>/?/init.lua`, `<корень>/src/?.lua`, `<корень>/src/?/init.lua`.

**Пункт Tarantool не появился в New Project** — перезапустите IDE после
установки плагина: список генераторов строится при старте.

**Источник данных не подключается («Couldn't connect to the server»)** —
инстанс не запущен: проверьте панель Tarantool и нажмите «Запустить»
(или `tt start` в терминале). Порт и учётные данные — в `config.yaml`.
